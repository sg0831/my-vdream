## 3. 함께 처리한 기술 항목

| 항목 | 내용 |
|---|---|
| Alembic | 초기 스키마 + 순환 FK 마이그레이션. 컨테이너 시작 시 `alembic upgrade head` |
| MySQL 데모 초기화 버그 수정 | `users ↔ companies` 순환 FK 때문에 MySQL에서 두 번째 초기화가 실패하던 문제를 발견. FK를 `use_alter`로 분리하고, 초기화를 TRUNCATE 방식으로 바꿔 Alembic 스키마를 건드리지 않게 함 |
| 로그인·업로드 속도 제한 | slowapi. 로그인·데모 로그인 20회/분, 업로드 10회/분. Caddy 뒤에서도 실제 접속 IP로 세도록 `--proxy-headers` 적용 (모든 방문자가 한 IP로 묶이던 문제 수정) |
| S3 호환 저장소 | `S3_ENDPOINT` 설정 추가(MinIO 등). 경로 방식 주소, SigV4 |
| OpenAPI → TypeScript | `scripts/generate-types.sh`로 `src/api-schema.d.ts` 생성, 요청 타입 일부 적용, CI에서 생성물 일치 검사 |
| 프론트 테스트 | Vitest + Testing Library 4개 |
| 번들 분할 | 역할 영역별 `lazy()`와 MUI·차트 청크 분리 (500KB 경고 해소) |
| 데모 딥링크 | `/demo/worker`, `/demo/company`, `/demo/manager`, `/demo/admin` → 해당 역할로 바로 로그인 (이력서 링크용) |
| CI | sqlite 테스트 + S3 통합, MySQL 8.4 + Alembic upgrade/check + 테스트, 프론트(타입 생성물·tsc·Vitest·빌드), Docker 빌드 |

## 4. 남은 작업 (기능 외)

| 항목 | 상태 | 이유와 방법 |
|---|---|---|
| AWS 배포 | 미실행 | EC2·도메인·S3·IAM은 사용자 AWS 계정 작업. 같은 Compose 구성을 로컬에서 끝까지 검증했으므로 README 배포 절차대로 진행하면 된다 |
| GitHub 저장소·브랜치 보호·Actions 실행 | 미실행 | 사용자 GitHub 계정 작업. 워크플로 YAML 문법은 검증함 |
| 스크린리더 실제 점검 (VoiceOver·NVDA) | 미실행 | 사람이 직접 들어 봐야 하는 수동 점검. Lighthouse 자동 검사는 모두 100점 |
| mypy | 경고 61건 | 대부분 `contract`처럼 NULL 가능 관계의 접근에 대한 타입 좁히기 경고. 테스트에서 드러난 실행 오류는 없음. CI 게이트에서는 제외 |
